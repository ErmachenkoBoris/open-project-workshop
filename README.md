# Open Project Workshop

**Код есть. А деньги?** — статический React-практикум в двух блоках. В первом участники выбирают идею и обсуждают её в паре. Во втором считают экономику рекламной кампании по выбранной модели дохода.

## Запуск

```sh
npm ci
npm run dev
npm run build
```

GitHub Pages собирает Vite в `dist/` через GitHub Actions. На опубликованной странице кнопка «QR для воркшопа» показывает QR текущего адреса и позволяет скачать PNG. Ответы и текущий шаг сохраняются в localStorage браузера участника.

## Экономика кампании

- CPA регистрации можно ввести напрямую или рассчитать как CPC ÷ конверсия клика в регистрацию. Число регистраций равно бюджету ÷ CPA. Если известно желаемое число регистраций, бюджет равен числу регистраций × CPA. Для сценария без платной рекламы вводится ожидаемое число регистраций, рекламный расход равен нулю.
- Для платной модели CAC равен CPA ÷ доля регистраций, дошедших до первой оплаты.
- LTV вклада равен средней выручке за срок жизни клиента × маржинальность. Для подписки выручка учитывает ожидаемое число оплаченных месяцев. Для комиссии — число сделок и долю проекта. Для рекламного дохода LTV рассчитан по среднему зарегистрированному пользователю. Показы незарегистрированным гостям можно оценить отдельно, их выручка входит в общий прогноз.
- Вклад регистрации в платной модели равен доле плательщиков × LTV вклада плательщика − доля неплательщиков × расходы на неплательщика. Для рекламной и пользовательской модели берётся LTV среднего пользователя.
- Смету можно ввести суммами или по статьям. Регулярные расходы автоматически входят в итог месяца. Разовые расходы входят в результат месяца запуска и прогноз за весь срок. Рекламные расходы берутся из раздела привлечения, и не требуют повторного ввода. Годовую цену домена распределяем на 12 месяцев.
- Вклад когорты после рекламы равен числу регистраций × вклад регистрации − рекламный расход. Чистый вклад когорты дополнительно вычитает разовые расходы запуска.
- Предельный CPA и минимальная цена рассчитаны до разовых расходов запуска. Срок возврата привлечения предполагает одинаковый вклад за каждый месяц. Порог окупаемости по бюджету рассчитан при неизменных CPA и конверсии.
- Результат бизнеса за месяц считается по суммам, относящимся к этому месяцу, по всем когортам. По умолчанию месячная выручка рассчитывается из модели дохода и ожидаемого числа новых пользователей. Расходы на продажи в этом режиме определяются маржинальностью. Для фактических поступлений можно переключиться на ручной ввод. Ранее сохранённые сценарии с указанным объёмом остаются доступны в черновике. В него не включён ещё не полученный прогноз LTV.
